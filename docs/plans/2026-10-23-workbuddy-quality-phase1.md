# WorkBuddy 云答题第一批实施清单

**Goal:** 在不改变答案 JSON 协议、不接触部署目录官方 Jev 配置的前提下，交付可诊断、可固定模型、可拒绝损坏输入、可同题对照的云答题实现。

**Architecture:** 云模型选择、专用提示词、流式响应校验与安全诊断集中到独立模块；原 Jev 决策策略及 OpenAI 提示词保留。浏览器补完整输入检查和可关闭的选项核对；评测脚本直接访问云 SDK，完全绕过 Jev。

**Tech Stack:** Node >=22.12，现有 WorkBuddy Cloud SDK，Playwright；不新增依赖。

**Spec:** `docs/plans/2026-10-23-workbuddy-answer-quality.md` 第一阶段（用户已批准）。按清单顺序执行与验证；不在本轮引入第二阶段多模型复核或新答案状态协议。

## 约束

- 只修改发布仓库；不读取、改写部署目录的 `config.json`、Jev Key、浏览器档案或本地控制台。
- 仅实网模型列表及明确标注的云单独评测可读取本地 WorkBuddy 公共配置；认证信息不进入日志、报告或仓库。
- `/answer` 的成功返回仍为 `{answers:[{id,letters}]}`。诊断不影响作答结果；已有服务身份、Origin、Host、令牌校验保留。
- 真实准确率改善必须有同题对照；单元测试通过不等于答案准确率提高。

## 实施与验证

- [x] 云模型固定选择、专用提示词和坏输入检查；不可用模型、损坏输入与主动空答案均有回归覆盖。
- [x] 增加默认关闭的脱敏逐题诊断与请求关联，日志失败不影响答题、日志不含秘密。
- [x] 浏览器补图片/公式/乱码拦截与返回选项、实际选中及保存值的核对日志；重新构建两个脚本。

- [x] Node 22/24全量212项均通过，生成脚本一致性与Edge回环复测通过；真实云对照108题/432组，结果和限制见验收回执。
