# 首次脚本加载失败后的恢复

结论：修复首次注入失败后状态栏永久不可操作的问题。当前学习页已单独恢复，后续探测确认视频继续播放。新启动恢复逻辑随下一次正常启动 runner 生效；没有强制关闭当前课程浏览器。

## 原因和修复

现场右下角状态栏存在且属于当前文档，但开始/重启按钮均禁用，没有本项目控制器，旧 `__WB_BOOTED` 却已为 true。控制台记录首次注入失败；之后可信 `__WBGetScripts` 绑定已能返回匹配身份的脚本，且包含视频弹题适配。旧 bootstrap 在请求前就设置永久布尔标记，失败只输出控制台错误，没有重试或启动失败的按钮处理。

`wb-runner-runtime.mjs` 改为文档级启动状态：首次请求失败后间隔1秒重试，最多3次；耗尽后显示提示并允许“重新启动”重新拉取当前脚本。只在控制器确实创建后标记成功，不依赖页面自身的 `app` 对象；同文档重复初始化不重复请求。离页取消定时器，文档/URL变化后丢弃迟到结果。执行错误与获取错误分开，执行过的脚本不会自动反复重放。移除原生控制器不需要的 jQuery 等待；V3仍默认关闭，装载前先设置 console 驱动标记。

不改变可信顶层页面限制、健康/脚本身份核验、回环权限范围或令牌协议。启动状态不保存脚本源码/令牌，不输出原始错误详情。正常控制器接管后，启动状态栏处理不会覆盖其按钮和消息。

## 范围与 OPEN

本轮仅修改 runner 的内部 bootstrap、对应测试与说明，不修改服务、launcher、浏览器引擎、Jev配置或本地EXE。用户API Key和浏览器登录档案未读写。

OPEN：当前 runner 进程已将旧启动注入载入内存。磁盘已同步新逻辑，当前学习页通过可信绑定恢复；下次正常关闭并通过本工具打开浏览器才会加载新的启动恢复策略。没有把磁盘变更说成旧进程已热更新。

OPEN：未验证所有学校皮肤、真实弹题答案正确率、上游长期可用性或未来整课程不再出现其他问题。启动恢复不重启后台服务，不尝试不同选项、不绕过平台反馈。
